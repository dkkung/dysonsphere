Domain-specific charts live in **extension packages**, released separately from the core. After
installation, their charts appear under a namespace on `ds`:

```sh
pip install dysonsphere-biology
```

```python
import dysonsphere as ds

ds.biology.volcano(df, labels="gene", subset=8)
```

The first extension is [`dysonsphere-biology`](/extensions/biology/) (volcano plots today, more
genomics charts coming). If you want to build your own, see
[writing an extension](/extensions/authoring/).

## Why separate packages

Extensions carry heavy, domain-specific dependencies - a biology package may pull in pyBigWig,
pysam, or bioframe. Bundling those into core would force every user to install a genome-file
stack they may not need. Each extension is a separate distribution with its own release cadence
and optional dependencies, imported lazily with a clear error if missing. Install only the domains
you use.

Each extension is a separate top-level package and registers an entry point. This avoids adding domain dependencies to the core package and lets extensions release independently.

## Discovering what's installed

```python
import dysonsphere as ds

ds.extensions()            # -> ['biology']  (sorted names of installed extensions)

vol = ds.load_extension("biology")   # import one by name
vol.volcano(df, ...)

ds.biology.volcano(df, ...)          # or reach it as an attribute (resolved + cached)
```

- **`ds.extensions()`** lists the names of every installed extension (each package that
  registered under the `dysonsphere.extensions` entry-point group).
- **`ds.load_extension(name)`** imports one by name, raising an `ImportError` that names the
  installed set if it isn't there.
- **`ds.<name>`** (e.g. `ds.biology`) resolves the extension lazily on first attribute access
  and caches it. A missing extension raises the usual `AttributeError`.

These functions use package attribute access and entry-point discovery. Installing an extension is sufficient; the core package does not need edits.

## Extensions use documented APIs only

Extension charts use the same export behavior as core charts: generated helper data is filtered by
`ds.metadata.read(what="data")`, and their styling tracks the active theme and darkmode. They achieve
that through **`dysonsphere.ext`** - a small, stable, versioned API containing the core primitives an
extension needs, so extensions do not use `_`-private internals. The [authoring guide](/extensions/authoring/) shows how to use this API.
