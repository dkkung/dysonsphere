title: Saving, reading, loading
description: Export figures with metadata, read embedded information, and rebuild charts from JSON.
---

`ds.save()` embeds provenance, the resolved theme, and any chart statistics in exported files by
default. JSON exports also contain the chart specification and captured data. `ds.metadata.read()`
reads the embedded information, and `ds.load()` rebuilds a chart from JSON.

## Saving

```python
import dysonsphere as ds

ds.theme()
# ... build `chart` ...

ds.save(chart, "figure")
```

By default, this writes `figure.svg` and `figure.json`. Set `format=` to `"svg"`, `"png"`, `"json"`,
or `"html"`, as a string or list. Set `background=` to `"light"`, `"dark"`, or both. When both
backgrounds are exported, filenames use `_light` and `_dark` suffixes; a single background uses the
base filename.

```python
ds.save(chart, "figure", format=["svg", "png", "json"], background=["light", "dark"])
ds.save(chart, "figure", format="html")   # a self-contained interactive HTML page
```

Altair renders notebook previews directly from Vega-Lite, so SVG post-processing can make a
preview differ from a saved file. `ds.show(chart)` applies the same processing as `save()` and
returns the result as HTML.

`show()` follows the theme, including `transparent`; `save()` defaults to a transparent background
so exports can composite onto a page. The HTML wrapper displays the SVG against the notebook's own
background. This avoids the white image canvas that can make a transparent dark-mode figure
unreadable.

Static SVG and PNG output receives additional processing: `<g>` wrappers are flattened for
Illustrator, axis and log/power minor ticks are snapped to exact positions, superscripts are
realigned, and Latin statistical symbols such as *P* and *n* are italicized. Digits, operators, and
Greek symbols stay upright.

### Fonts

Fonts are referenced by name rather than embedded, so the viewing system uses the named font or an
available fallback. Set `theme(font="...")` to request another installed family. SVG exports use
the PostScript name `HelveticaNeue` for Adobe Illustrator.

In `show()` and static SVG/PNG output, the default `theme(fontGreek="Symbol")` switches only
Unicode Greek letters to the named font. The text stays unchanged; Latin letters, numbers,
punctuation, operators, the micro sign (`µ`), and explicit italic runs keep their styling.

Set `fontGreek=None` to disable the switch or use another installed family. Interactive HTML and
bare Altair output do not apply it.

An unavailable font may fall back to a system font. A font name alone does not establish journal
compliance.

<a id="what-gets-embedded" />
## Embedded metadata

When `saveMetadata=True` (the default), `save()` writes a `dysonsphere` metadata block into every
output format: JSON, SVG, PNG, and HTML.

- **provenance** - the user, time, chart expression when available, rendering environment, and
  checksums for the specification and captured data.
- **theme** - the resolved `ds.theme()` arguments for recreating the theme settings.
- **statistics** - the structured records from any `ds.stats.comparisons()` / `ds.stats.correlation()` on the
  chart (exact p-values, effect sizes, descriptives).
- **report** - the human-readable version of those statistics.

<a id="what-the-embedded-metadata-looks-like" />
## Structure of embedded metadata

This example uses a strip plot with a Kruskal-Wallis comparison on the `cars` dataset:

```python
strip = ds.mark_strip(cars, "Origin", "Miles_per_Gallon", origins)
mpg_comparisons = ds.stats.comparisons(
    cars, "Origin", "Miles_per_Gallon",
    [("USA", "Europe"), ("USA", "Japan")],
    test="kruskal", omnibusVerbose=True, categories=origins,
)
ds.save(strip + mpg_comparisons, "mpg_by_origin", format="json")
```

`ds.metadata.read("mpg_by_origin.json", what="metadata")` returns a `dict` with four keys:
`provenance`, `statistics`, `theme`, and `report`. Provenance includes the user, time, chart
expression when available, rendering environment, and checksums. The OS and vl-convert version help
identify the environment used to measure text:

```json
{
  "user": "dkkung",
  "script": "mpg_by_origin.py",
  "chart": "strip + mpg_comparisons",
  "timestamp": "2026-07-08T22:55:35Z",
  "environment": {
    "os": "macOS-26.5.2-arm64-arm-64bit",
    "python": "3.11.8", "altair": "6.2.1", "vl_convert": "1.9.0.post1",
    "dysonsphere": "3.5.0", "numpy": "2.4.6", "scipy": "1.17.1", "polars": "1.41.2"
  },
  "vegaliteChecksum": "sha256:53a99fe9a0e4ad703751014765e01a7f0860d7d89a78add9d50ead172f7aa9f2",
  "exportIdentifier": "ef49895a-2e06-495a-86d3-7b0f2980cd8b",
  "dataChecksum": ["multiset-sha256:281a94603a8549cda02866679f34c8d0d5ed490d3944c5ab881423ff388b52e8"]
}
```

The `chart` field records source text for the `chart` argument when available at the `save(...)`
call site. Here it is `strip + mpg_comparisons`; a variable passed directly is recorded by name.
Interactive sessions may not provide source text.

### Provenance identifiers

These fields identify the chart, data, and export in different ways:

- `dataChecksum` stores one order-independent checksum per captured dataframe. Its
  `multiset-sha256:` value hashes row digests, so row order does not affect it and it cannot be
  recreated by hashing the export file.
- `vegaliteChecksum` identifies the normalized Vega-Lite specification, excluding `usermeta`. A
  `sha256:` value hashes the canonical specification.
- `exportIdentifier` is shared by all formats and backgrounds written by one `save()` call.

An export built by an extension may also record its version in `environment`.

### Captured data

For a JSON export, `ds.metadata.read("mpg_by_origin.json", what="data")` returns the data included
in the specification. Here it is the 398-row dataframe, including Altair-inlined transform
columns such as `jitter_x` but excluding Dysonsphere annotation layers such as bracket coordinates
and error bars. Data absent from the specification cannot be recovered.

## Reading it back

```python
ds.metadata.read("figure.json")                    # the human-readable report (default)
ds.metadata.read("figure.json", what="statistics") # structured records (list of dicts)
ds.metadata.read("figure.json", what="metadata")   # the whole dysonsphere block (shown above)
ds.metadata.read("figure.json", what="data")       # the original DataFrame
```

`ds.metadata.read()` reads metadata and reports from JSON, SVG, and PNG. Use `what="data"` for JSON
only; JSON carries the full data. `what="data"` returns the user's frame. Choose its output type
with `output=` (`"polars"`, `"pandas"`, `"duckdb"`, or `"records"`).

## Verifying a figure

`ds.metadata.verify()` re-checks a figure against the checksums it carries, with no access to the original
script:

```python
ds.metadata.verify("figure.json")                   # was the spec edited after export?
ds.metadata.verify("figure.png", data=df)             # did this figure come from this data?
ds.metadata.verify("figure.json", data=[counts, meta]) # multi-frame chart
```

It returns a `ds.metadata.VerifyResult` (shown below as its printed representation):

```python
VerifyResult(
    path='figure.json',
    specValid=True,
    dataMatches=True,
    storedDataChecksums=['multiset-sha256:57ae424f2a1d3887eaed57bd8733b7a256d1f6f7370a55cc3458bd14a19f928b'],
    computedDataChecksums=['multiset-sha256:57ae424f2a1d3887eaed57bd8733b7a256d1f6f7370a55cc3458bd14a19f928b'],
    exportIdentifier='0513f023-4667-4367-8883-e8762571811d',
    timestamp='2026-08-03T23:56:06Z',
)
```

| field | |
| --- | --- |
| `specValid` | for JSON, the specification excluding usermeta still hashes to the recorded `vegaliteChecksum` |
| `dataMatches` | the frames you passed hash to the recorded `dataChecksum` |
| `storedDataChecksums` | what the file recorded |
| `computedDataChecksums` | what your frames hash to now - the two differ only when `dataMatches` is `False` |
| `exportIdentifier` | the `ds.save()` call that produced the file; every format and background of one save shares it |
| `timestamp` | when that save ran |
| `matches` / `groups` | filled only when comparing a list - see below |
| `.ok` | every check that actually ran passed |

Both checks are tri-state: `None` means the check could not run, not that it failed. SVG and PNG
carry checksums but not the full specification, so `specValid` is `None` for those formats while
`dataMatches` can still be checked. `.ok` treats `None` as "not a failure." Neither row order nor
the order of dataframes affects the result.

The result fields show which check did not match:

```python
r = ds.metadata.verify("figure.json", data=edited)
r.ok           # False
r.specValid    # True  - the file itself is intact
r.dataMatches  # False - but it did not come from this data
```

If a file no longer contains its metadata, `ds.metadata.verify()` raises because there are no
stored checksums to compare. `ds.metadata.frame_checksum(df)` computes a checksum from the dataframe;
use it to compare that dataframe with an intact export or with a separately recorded checksum.

<a id="which-field-answers-which-question" />
## Interpreting embedded metadata

Three provenance fields answer different questions:

| question | field |
| --- | --- |
| Is this the same chart? | `vegaliteChecksum` - content identity, unchanged by re-saving |
| Did these files come from one `ds.save()` call? | `exportIdentifier` - shared by every format and background of one save |
| Is this the same underlying data? | `dataChecksum` - unchanged by restyling the chart |

## Comparing figures

Pass a list to `ds.metadata.verify()` to compare figures:

```python
ds.metadata.verify(["fig1.json", "fig2.png", "fig3.svg"])
```

```python
matches   {"spec": False, "data": True,  "save": False}
groups    {"spec": {"fig1.json": 0, "fig2.png": 0, "fig3.svg": 1},
           "data": {"fig1.json": 0, "fig2.png": 0, "fig3.svg": 0},
           "save": {"fig1.json": 0, "fig2.png": 1, "fig3.svg": 2}}
```

`matches` reports whether all items agree. `groups` assigns group numbers when they differ. In the
example, the first two share a spec group, all three share a data group, and the save groups differ.

Items may be saved files in any format, or Altair charts you have not saved yet - so
`ds.metadata.verify(["published.json", chart])` asks whether the figure your script builds today still
matches the one you published. A chart in memory has no export identity, so `"save"` comes back
`None` for the whole call. `what=` narrows it: `what="data"` asks only about the data.

Use `"spec"` to compare chart specifications. Two saves of an identical chart have the same spec
checksum but different export identifiers, so `"save"` reports a difference when a figure is
re-exported.

:::note
List comparisons use the values recorded in each file, which allows a PNG to be compared with JSON
even though PNG has no specification to re-hash. An edited file can still compare as the chart it
claims to be. Verify a JSON file on its own to detect a changed specification.
:::

## Reproducible exports

A build script normally changes `timestamp` and `exportIdentifier` on every save, even when the
specification and data are unchanged. The checksums remain based on the spec and data.

Set [`SOURCE_DATE_EPOCH`](https://reproducible-builds.org/specs/source-date-epoch/), the
cross-tool convention for this, to an integer count of UTC seconds:

```bash
SOURCE_DATE_EPOCH=$(git log -1 --format=%ct) uv run python build_figures.py
```

With `SOURCE_DATE_EPOCH` set, repeated saves of an unchanged figure are byte-identical. The
recorded timestamp is the supplied value, not the time of the save.

Nothing else about the metadata changes - same fields, same shapes. Two values differ:

| | default | pinned |
| --- | --- | --- |
| `timestamp` | the real save time | the instant you supplied |
| `exportIdentifier` | a random UUID, new every save | a UUID derived from the figure's timestamp, spec, and data |

The pinned timestamp does not record when the export ran. Separate saves with identical inputs can
also share an identifier. An invalid value raises an error instead of falling back to the current
time.

## Rebuilding the chart

```python
chart = ds.load("figure.json")            # an Altair object, theme re-applied
spec  = ds.load("figure.json", raw=True)  # the untouched Vega-Lite spec dict
```

`load()` accepts only JSON, which contains the full specification. It reapplies the saved theme so
the reconstructed chart renders the same way.

The rebuilt Altair object has no metadata. `load()` strips `usermeta` and `config` because Altair's
schema rejects some theme config values. The object therefore has no checksums for verification.
Pass the file to `ds.metadata.verify()` instead:

```python
ds.metadata.verify("figure.json", data=df)                    # yes - reads the file
ds.metadata.verify(ds.load("figure.json"))                  # no - the object has no metadata
```

`ds.load("figure.json", raw=True)` does keep `usermeta`, since it returns the spec untouched.

## Statistics without a file

`ds.stats.comparisons()` and `ds.stats.correlation()` can surface their report directly:

```python
chart = base + ds.stats.comparisons(df, "group", "value", pairs, test="anova", report=True)
# report=True prints it; saveReport="dir/" writes a timestamped .txt
```

<a id="how-the-fields-map-to-provenance-standards" />
## Mapping fields to provenance standards

Dysonsphere uses its own field names, but each concept has a counterpart in an established
provenance vocabulary:

| dysonsphere | Equivalent |
| --- | --- |
| `user` | W3C PROV `Agent` + `wasAttributedTo`; Dublin Core `dcterms:creator` |
| `script` | PROV `Plan` / `hadPlan` |
| `chart` | no equivalent in any standard |
| `timestamp` | PROV `generatedAtTime`; `dcterms:created` |
| `environment` | SLSA `runDetails.builder.version` |
| `vegaliteChecksum` | in-toto `subject[].digest` |
| `exportIdentifier` | SLSA `metadata.invocationId`; XMP `xmpMM:InstanceID` |
| `dataChecksum` | SLSA `resolvedDependencies[].digest` |

No single standard covers the whole block. PROV, Dublin Core, and XMP describe who and when but do
not provide a content digest; SLSA and in-toto provide digests but do not describe a human author or
chart expression. The metadata block is plain JSON rather than an implementation of any one of
these standards.
