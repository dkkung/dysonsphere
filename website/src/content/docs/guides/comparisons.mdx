[`ds.stats.comparisons()`](/reference/stats/#comparisons) computes significance tests with scipy
and draws the results as a layer composed with `+`. Each call also builds a structured report of
descriptives, exact p-values, and effect sizes. `save()` embeds the report in the export metadata;
`report=True` prints it, and `saveReport=True` writes it to a text file.

The `test=` argument selects a pairwise test (`mannwhitneyu`, `ttest_ind`, `ttest_rel`, `wilcoxon`,
`tukey_hsd`) or an omnibus test (`anova`, `kruskal`, `friedman`, `alexandergovern`). This example
uses an ANOVA corner label and two post-hoc brackets. The annotation reserves space at the top of
the y axis for the brackets:

<Example name="comparisons" alt="Fuel economy by origin with an ANOVA label and post-hoc brackets" />

## Pairwise tests

Specify the group pairs to test. Each pair gets a bracket, stacked to avoid overlap.

The `correction=` option applies a multiple-comparison adjustment across the full family. Use
`"holm"` or `"bonferroni"` for family-wise error control, or `"fdr_bh"` or `"fdr_by"` for
false-discovery control.

<Example name="comparisons_pairwise" alt="Three pairwise Mann-Whitney brackets with Holm correction" />

### Every pair at once

`pairs="all"` expands to every unique pair, in `categories` order. By default, the correction
family size is the number of pairs. If you tested additional pairs that are not listed, set
nComparisons to the size of the full family.

<Example name="comparisons_all" alt="All three pairwise comparisons between car origins" />

The number of brackets grows as `n(n-1)/2`. The number of stack rows depends on the largest set of
mutually overlapping brackets and grows roughly as `n²/4`: 5 rows at four groups, 8 at five, and 11
at six. When comparing more than four or five groups, an omnibus test can report every pairwise
post-hoc result without drawing brackets.

### Compare against a control

Pass `reference=` (a group name) to compare every other group with one control. The p-value appears
above each non-reference mark without a bracket. If `pairs` is unset, the function derives these
comparisons. It supports pairwise tests and adjusts p-values across the full family. Labels appear
above each group's data; styling the reference group (for example, with a darker fill) is up to you.
In grouped mode, `reference` names an `xOffset` level compared within each category.

<Example name="comparisons_reference" alt="Dose-response bars compared to a control with asterisks over each bar" />

Reference labels are placed a fixed pixel distance above each group's observations. This example
uses three dose-response groups, a darker vehicle control, quasirandom points, and error bars:

<Example name="comparisons_grouped_reference" alt="Three dose-response groups with an asterisk above each dose bar compared to a darker vehicle control" />

## Omnibus tests

An omnibus test evaluates all groups together. It produces one initial p-value; use it when you
have three or more groups and no specific pair was defined in advance.

Set `test=` to `anova`, `kruskal`, `friedman`, or `alexandergovern` to place the result in a corner
label rather than on a bracket. Adding `pairs` draws brackets using the default post-hoc test for
each omnibus test: ANOVA → Tukey HSD, Kruskal-Wallis → Dunn, Friedman → Nemenyi, and
Alexander-Govern → Games-Howell. Set `postHoc=` to override the default.

`omnibusVerbose=True` adds the test statistic, degrees of freedom, and an effect size (η², ε², or
Kendall's W depending on the test).

<Example name="comparisons_kruskal" alt="Kruskal-Wallis omnibus label with Dunn post-hoc brackets" />

With `pairs` unset, only the omnibus corner label is drawn. The report still includes every
pairwise post-hoc comparison.

## Styling

### Bracket shape

`bracketStyle` takes `"bracket"` (the default, a bar with end ticks), `"line"` (bar only), or
`"drop"`.

In `"drop"` mode, each end tick extends toward its group and stops before reaching the data or
crossing another element. Ticks in the same column are staggered. This connects each bracket to its
group, particularly when brackets span one another:

<Example name="comparisons_drop" alt="Comparison brackets whose end ticks reach down toward each group" />

This style works best with a few brackets over groups of similar height. All brackets share a stack
height, so one tall group can raise the stack and lengthen lower end ticks.

### Direction

The `reverse=` list places the named brackets below their groups with the ticks pointing up. Reversed
and normal brackets can appear in the same chart. Use this when space above the data is limited.

<Example name="comparisons_reverse" alt="Two comparison brackets hanging below the data with labels beneath" />

### Label styles

`labelStyle="asterisks"` renders `*` / `**` / `***` / `ns`; `bracketStyle="line"` drops the end
ticks.

<Example name="comparisons_asterisks" alt="Pairwise comparison with asterisk labels and line brackets" />

`labelStyle="value"` renders the number as `"p"` does, without the `P` symbol. It retains operators
such as `< 0.001` when values are floored. This example sets `yPositions=` to one number, placing
every label in a flat row:

<Example name="comparisons_value" alt="Reference comparison with bare-value labels in a flat row" />

### Number notation

`notation=` controls the p-value format (`"scientific"`, `"e"`, `"power"`), and `sigFigs=` sets the
precision.

Zero p-values are displayed as bounds in every notation, using the minimum normal positive float
as the record bound; they are not reported as exact zero. Positive subnormal p-values remain valid.

<Example name="comparisons_notation" alt="Comparison bracket with scientific-notation p-value" />

### Per-pair control

Both `bracketStyle` and `notation` also accept a dict for per-pair control. Pair keys match regardless
of order; `notation` also accepts a `"test"` key for the omnibus label:

<Example name="comparisons_perpair" alt="Two brackets with different per-pair styles and notation" />

### Placement

In automatic placement, brackets appear above the data they span. Overlapping brackets are separated
by a constant pixel gap, independent of the y-range. Use the following parameters to set placement
explicitly.

`yPositions=` sets exact heights. One number puts every label in a flat row; a list gives one height
per comparison. `yStart=` sets the stack's base and `yStep=` the gap between rows, both in data
units. `yPad=` adjusts the gap from the data while retaining automatic placement. Supplying any of
them opts the chart out of pixel placement, so the gaps then follow the y-domain.

<Example name="comparisons_placement" alt="Three comparison brackets on an evenly spaced manual ladder" />

`pvalues=` draws final numbers supplied from somewhere else. In pairwise mode it skips the test;
correction and pair effects are not computed. In omnibus mode,
the omnibus test still runs, but the report contains only the requested supplied pairs; without
supplied values, an omnibus report contains every post-hoc pair.

Statistical columns used by the annotation must exist and contain numeric, finite observations.
Missing or non-finite group IDs and required computed results raise an error; unrelated dataframe
columns are ignored. Supplied p-values must be real, finite, non-bool numbers in `[0, 1]`.

## Grouped (two-factor) comparisons

For a grouped bar chart with a subgroup on `xOffset` within each x-category, such as a qPCR gene ×
condition panel, pass `xOffset` to compare subgroup levels within each group. `pairs` names the
levels; with two levels, it defaults to their single pair. One bracket is drawn per x-category, using
a test for that category and sitting above its bars. Set `categories` and `xOffsetSort` to match the
chart's `x` and `xOffset` orders. Explicit orders must include every observed value exactly once; the
sequence order, including for numeric categories, is preserved:

<Example name="qpcr" alt="Grouped qPCR bars with a within-gene significance bracket per gene" />

Grouped mode supports the pairwise tests only. `postHoc` is not supported; notation mappings and
`yPositions` lists are rejected. Grouped test-label options still apply to the shared test label.
When correction is used, `nComparisons` must be a positive non-bool integer at least as large as
the full computed family (`categories × pairs`), even if fewer brackets are drawn. A larger value
is allowed. Supplied p-values are not corrected again.

`reverse=` and `bracketStyle="drop"` also work here. In grouped mode, `reverse` names xOffset levels,
like `pairs`, and applies in every category:

<Example name="comparisons_grouped_reverse" alt="Grouped comparisons with brackets hanging below each pair of conditions" />
