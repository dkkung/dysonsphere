## Text

`ds.text()` places annotations at data coordinates (numbers share the quantitative scale, strings
use categories) or at frame positions via nine presets (`topLeft`, `middleCenter`, …). Add a
background chip behind the text with `fill` (`True` for a darkmode-aware grey, or a color),
`fillOpacity`, `stroke`, and `cornerRadius` to keep text legible over the plot. The chip is drawn
only when `fill` is set.

## Point labels

`ds.labels()` places text labels with collision-aware connector lines for points, such as volcano
genes, ranked values, or clusters. Placement is deterministic and uses no random selection: a
bounded search prefers nearby open positions, and straight connectors can slide along a label's
visible boundary to avoid other points. Adjacent labels omit short connectors unless
`alwaysShowConnectors=True`. Forced connectors reserve their full endpoint clearances. If a requested
gap or label cannot fit in the panel, the connector is omitted rather than drawn through a mark.
Pass the full plotted `data` and let `subset=` select which points to
name – an integer picks that many spread evenly across the plot, a list names rows by their
`labels` column value, and a boolean mask (`subset=df["is_hit"]`) selects rows positionally when the
label column repeats. Passing the full `df` also lets the labels dodge every plotted point, not
just the ones being named, so they settle into open space instead of on top of the crowd. Style
the labels with `fontSize`, `color`, and `fontStyle` (e.g. `fontStyle="italic"` for gene or
species names), and give them a background chip with `fill` / `fillOpacity` / `stroke` /
`cornerRadius` (drawn only when `fill` is set) to keep them readable over a dense scatter.

Labels are centered, using approximate character-aware text bounds. Connectors prefer edge-body
attachments, allowing facing corners for diagonal approaches rather than detached, edge-parallel stubs.
The initial point coordinates and label settings are saved with the layer. When you call `ds.save()` or
`ds.show()`, dysonsphere evaluates the complete composed panel and places labels again against visible
sibling points, straight lines and rules, rectangles, and fixed text – including marks added
before or after `ds.labels()`. The saved coordinates and settings survive `ds.load()`, resizing, and nested
concat composition; no extra placement call is needed. An omitted `connectorGap` increases when needed
to clear the rendered symbol plus whitespace, while an explicit zero or numeric value remains exact.
Arbitrary curves, areas, images, and paths are not treated as exact obstacles. Every requested label
remains visible, so an overfull plot may still contain overlaps. Bare Altair display
uses the initial placement; use `ds.show()` to preview the saved layout.

Set `connectorCap="arrow"` to point each connector toward its target. The existing `connectorGap`
controls target clearance and is applied once; label placement and text-end clearance do not change.
Arrowheads appear in SVG/PNG output from `ds.save()` and in `ds.show()`, but not in raw Altair
display or interactive HTML. This example saves SVG and PNG:

```python
arrow_labels = points + ds.labels(data, "x", "y", "name", connectorCap="arrow")
ds.save(arrow_labels, "arrow-labels", format=["svg", "png"])
```

## Superscripts and subscripts

Axis titles, `ds.text` annotations, and legend titles can use superscript or subscript notation.
`ds.save()` typesets them when exporting; the site's live charts apply the same typesetting. Each
notation run is rendered smaller and shifted from the baseline, without relying on Unicode
super/subscript glyphs that the font may lack. Use a caret for superscripts and a **double**
underscore for subscripts:

- `x^2`, `10^3` -> x squared, ten cubed
- `C__t`, `x__1` -> C-sub-t, x-sub-1

The run is the next one or two characters after the token. Literal Unicode subscripts such as
`H₂O` and `t₀` are also handled.

<Example name="subscripts" alt="Concentration-decay line with a C-subscript-t axis title and a squared-superscript annotation" />

The subscript marker is a **double** underscore so single underscores in column names remain part
of the name. Without this distinction, default axis titles from columns such as `x_1` or
`flipper_length_mm` would be interpreted as subscripts if a lone `_` marked them. The `__` form
lowers deliberate tokens such as `C__t`, and its boundary check leaves ordinary names such as
`model__alpha` unchanged. Superscript notation uses `^` followed by one or two letters or digits; a
column name matching that pattern is also typeset as notation.
