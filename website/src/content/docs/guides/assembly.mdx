`ds.assemble()` composes charts into one figure, with each chart built at its own size. Members
are `(builder, width, height)` tuples, and you pass the *function*, not the chart.

```python
figure = ds.assemble(
    [(time_course, 210, 130), (endpoint_quant, 95, 130)],
    spacing=34,
)
```

`ds.theme()` cannot set a different size for each chart because all charts share a `config.view` –
the last call sets the shared size. `.properties()` changes chart dimensions but leaves
`markSize`, corner radii, and pixel annotations calculated for the theme's size. `assemble` runs each
builder with the theme set to that member's size, so `ds.shade` spans, comparison brackets, and
`ds.labels` placement use the matching dimensions.

Nest lists to make rows; `spacing` is a number, or `{"row": n, "column": n}`:

Rows are sized independently, so a wide chart does not stretch the column beneath it. Rows can
contain different numbers of charts, such as a wide track above three panels:

<Example name="assemble_rows" alt="A coverage track above three smaller panels" />

## Figure labels

A fourth element carries the panel's label – used verbatim and optional per member:

```python
[(time_course, 190, 110, "a"), (endpoint_quant, 90, 110, "b")]
```

It sits at the top-left of the chart area, outside the axis labels. Its own wrapper lets the chart
keep a `.properties(title=...)` title. `labelFontSize` (`8`),
`labelFontWeight` (`700`), `labelColor` and `labelOffset` style every label in the figure; the font
comes from `ds.theme()`. Labels sharing a column are aligned exactly, whatever each chart's axis
margin is.

## Reserved slots

`None` as the chart holds space for a panel you will composite in later, labelled so the lettering
stays in sequence:

<Example name="assemble_slot" alt="A four-panel figure whose first panel is a reserved empty slot" />

The slot is filled and outlined to match the axes, and is drawn at the specified size. A gap may
appear beside it: charts in a column align by their **plot** areas, while the slot has no axis labels
to fill the space its neighbors use. Changing the slot size does not remove that gap.

## Members

Anywhere a tuple works, a dict works, and an unknown key raises rather than leaving a chart at the
wrong size:

```python
ds.assemble([{"chart": time_course, "width": 190, "height": 110, "label": "a"}])
```

A bare builder uses the theme's current size. An already-built chart is used as-is. Since
`assemble` returns an ordinary Altair chart, its result can be nested in another call when rows need
different spacing:

```python
top = ds.assemble([(time_course, 190, 110), (endpoint_quant, 90, 110)], spacing=10)
bottom = ds.assemble([(heatmap, 130, 110), (activity_fit, 150, 110)], spacing=25)

figure = ds.assemble([[top], [bottom]], spacing={"row": 40})
```

## Styling and export

Vega-Lite's `config` is spec-level, so palettes, fonts, and axis styling cannot differ between
charts in one figure; `assemble` sets size only. Set those on the encoding instead, which is per-view
and survives:

```python
alt.Color("dose:N", scale=alt.Scale(range=ds.palette("cat3", 3)))
alt.X("dose:N", axis=alt.Axis(labelFontSize=9))
```

`ds.save(figure, "figure_1a")` exports it like any chart. Pass a callable when saving both
backgrounds, since a reserved slot resolves its fill against `darkmode` at build time. An assembled
figure may hold several dataframes, so `ds.metadata.read(path, what="data")` needs
`dataset="all"` or a name – see [saving and reading](/guides/saving/).

Charts made with `.facet()` or `.repeat()` render one chart repeatedly, so every panel uses the
theme `width`. Use `assemble` when charts need different sizes.
